# 阪大シャトル 広告・収益化仕様 v0.1

## 1. 目的

阪大シャトルの主要価値である「次の便をすぐ確認できる」「検索が速い」「時刻表が見やすい」を損なわず、将来的にGoogle AdSense等へ接続できる広告スロットを用意する。

初期段階ではGoogle広告を配信せず、**自社案内（House Ad）**として「阪大シャトルを友達におすすめしよう」を表示する。利用者が広告挿入後のUXを検証できる状態を先に作り、その後に外部広告へ差し替える。

## 2. 基本原則

1. 次便確認・検索・時刻表選択を広告より優先する。
2. 広告を便カード、検索結果、ナビゲーションに擬態させない。
3. 「1本前 / 1本後」「検索」「時刻表の行先切替」など高頻度タップUIの近傍には広告を置かない。
4. トップの「次の便」Hero、Bottom Sheet、sticky selector、bottom navigationには広告を置かない。
5. 外部広告は必ず「広告」表示を持ち、コンテンツと視覚的に区別する。
6. 現在地や検索経路を独自に広告ターゲティングへ渡さない。
7. CLS（表示後のレイアウトずれ）を抑えるため、外部広告スロットには最低高を確保する。

## 3. 広告配置

### A1 Home Feed

**位置:** 「このあとの便」セクションの後、最近使ったルートの前。

**理由:** 次便確認と行先選択を完了した後なので、最重要タスクを阻害しない。

**初期表示:** House Ad「阪大シャトルを友達におすすめしよう」

**将来:** Responsive in-page display ad。

### A2 Search Results

**位置:** 検索結果2件目の後。

**条件:** 結果が2件以上ある場合のみ。

**禁止:** 検索ボタン直下、検索結果1件目より前、前後便操作の直近。

**将来:** Responsive in-page display ad。

### A3 Timetable Feed

**位置:** 時刻表5便目の後に1枠のみ。

**理由:** Yahoo!乗換案内のようなフィード中広告の考え方は採用するが、通常便と誤認しないようカード形状・背景・ラベルを別系統にする。

**禁止:** 「次の便」ハイライト行の直前直後を広告専用アルゴリズムで狙わない。sticky selector内には置かない。

## 4. 現時点で採用しない形式

### Anchor Ads

モバイル下部には阪大シャトルのbottom navigationが常駐するため、Bottom Anchorは衝突しやすい。初期のGoogle広告導入ではOFFを推奨。

### Vignette Ads

経路検索アプリではページ復帰・画面ロック解除・タブ復帰が頻繁に起きる。フルスクリーン広告は「今すぐ次便を見る」という利用目的と相性が悪いため初期はOFF。

### 広告を便カードに見せるNative風実装

便情報との誤認や誤タップを招くため採用しない。

## 5. House Ad仕様

### コピー

- 見出し: `阪大シャトルを友達におすすめしよう`
- 補足: `豊中・箕面・吹田の移動を、もっと迷わず。`
- CTA: `共有する`

時刻表ではコンパクト版として:

- `友達にも、次の便を。`
- `便利だったら共有してみませんか？`

### 挙動

CTA押下時:

1. Web Share APIが利用可能ならOS共有シートを開く。
2. 非対応ならアプリURLをclipboardへコピー。
3. 利用者に広告クリックを求める文言は表示しない。

## 6. Ad Provider Architecture

`src/ads.mjs` が広告スロットの配置を管理する。

モード:

- `house`: 現在の自社案内。
- `adsense`: 将来のGoogle AdSenseマウント領域。
- `off`: 広告スロットなし。

スロットID:

- `home-feed`
- `search-results`
- `timetable-feed`

外部広告へ移行する際も検索ロジックや時刻表レンダリングは変更せず、Provider部分だけ差し替える。

## 7. Google AdSense導入時の要件

### 配置ポリシー

Google AdSenseでは、ナビゲーション、前後ボタン、ダウンロード等の操作UI付近で誤クリックを誘発する配置を避ける必要がある。また広告をサイトコンテンツに擬態させてはならない。

このため阪大シャトルでは、Google広告を明確な独立カードとして扱う。

### 推奨フォーマット

Phase 1:

- Responsive Display / In-page Bannerのみ
- Auto AdsのAnchor OFF
- Vignette OFF
- Multiplex OFF

Phase 2:

DAU・離脱率・誤タップ傾向を確認後に限定的に追加検討。

### Privacy / Consent

Google広告導入時はPrivacy Policyを公開し、必要な地域向けにGoogle認定CMPまたは適切なConsent Managementを設定する。

## 8. Hosting上の重要事項

現在のGitHub Pagesは開発・Previewには適しているが、GitHubはPagesを主に商用SaaSやオンラインビジネスを運営する無料ホスティング用途として使用することを制限している。

またAdSenseのサイト登録は通常、所有する標準ドメインを前提とする。

**したがって本番収益化前に以下を推奨する。**

1. 独自ドメイン取得。
2. Cloudflare Pages / Vercel / Netlify等へ本番配信を移行。
3. GitHub Repositoryは引き続きソース正本として使用。
4. 独自ドメインをAdSenseへ登録・審査。
5. `ads.txt`、Privacy Policy、CMPを整備。

## 9. 成長との接続

広告導入そのものを収益化の目的にせず、House Ad期間を利用して「共有による新規流入」がどの程度生まれるかを先に検証する。

見るべき指標:

- Share CTA率
- 共有リンクからの新規訪問
- DAU / WAU
- 1ユーザーあたり検索回数
- 7日継続率
- 広告挿入前後の検索完了率

広告収益は利用者規模に依存するため、まず阪大生内での利用密度を上げることを優先する。

## 10. 将来の収益化候補

Google AdSenseだけに依存せず、利用者数が増えた段階で以下も比較する。

- 学生向けサービス・店舗の直接スポンサー枠
- 学祭・学生団体向け期間限定告知枠
- 大学周辺店舗との固定スポンサー契約

ただし大阪大学公式サービスと誤認されるスポンサー表現は避け、非公式Webアプリである表示を維持する。
